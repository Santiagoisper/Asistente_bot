Resumen ejecutivo

¿Cómo leer este informe? Cada ítem técnico incluye una línea en gris que lo explica en lenguaje cotidiano. No hace falta saber de programación.

RAG = el sistema busca en los documentos del estudio y responde citando la página exacta, como un asistente que solo puede usar el protocolo cargado.

ALPHI es un asistente documental clínico con inteligencia artificial para sitios de ensayo clínico (CRC, enfermería, investigadores, monitores). Responde preguntas sobre protocolos, IBs y manuales de 200–400 páginas, con citas obligatorias al documento fuente. Si no hay evidencia suficiente, no responde — no inventa.

En la práctica: la coordinadora pregunta “¿este paciente cumple el criterio 3?” y ALPHI muestra la respuesta con el párrafo del protocolo donde lo dice — o admite que no encontró la información.
En una frase: Construimos el producto difícil (trial-ops regulado), no el producto fácil (chat genérico sobre PDFs). El código está; falta cerrar validación en sitio y escalar comercialmente.

Qué es ALPHI

Plataforma web multi-tenant B2B que combina tres pilares:

1

Chat RAG

Preguntas con respuestas ancladas y citas clickeables

Como preguntarle a un colega que solo puede mirar el protocolo y te señala la página exacta.
2

Study Spec

Criterios, visitas, endpoints extraídos del protocolo

Un resumen estructurado del estudio (quién entra, qué visitas hay, qué medir) sacado automáticamente del PDF.
3

Módulo clínico

Sujetos, evoluciones cifradas, screening, labs OCR

Registro de pacientes del ensayo, notas protegidas, chequeo de elegibilidad y lectura asistida de laboratorios.

Qué NO es ALPHI

  • No es un CTMS completo (Medidata, Veeva) — no reemplaza el sistema gigante que usa la industria para gestionar todo el ensayo de punta a punta.
  • No es generador de epicrisis para consultorio (Pacientry) — no escribe historias clínicas de consultorio ambulatorio.
  • No es ChatGPT sobre PDFs sin trazabilidad — no inventa respuestas ni mezcla conocimiento general con el protocolo.
  • No está certificado FDA Part 11 ni ISO 27001 (aún) — cumple en documentación y controles, pero aún no tiene sello oficial de auditor externo.

El problema que resolvemos

  • Paciente en sala → la coordinadora no puede salir 15 min a buscar en el PDF — necesita la respuesta en segundos, con la fuente.
  • Monitor pide evidencia trazable de una decisión operacional — hay que mostrar el párrafo del protocolo, no “me acuerdo”.
  • Onboarding de staff nuevo en estudios complejos — capacitar gente nueva sin leer 300 páginas de una sentada.
  • Evento adverso → verificar timeline SAE/SUSAR en minutos — plazos de reporte de eventos graves sin hojear el manual.
La fuente trazable es el producto, no el chat.

Contrato de producto (no negociable)

  1. Grounding-only — solo responde desde documentos del estudio activoSi no está en el PDF cargado, no lo dice.
  2. Citas obligatorias — cada afirmación lleva referencia verificableCada respuesta muestra página y sección del documento.
  3. LLM extrae, reglas deciden — el modelo no es juez de elegibilidad finalLa IA lee y organiza; las reglas fijas (no la IA) deciden si un paciente califica.
  4. Human-in-the-loop — spec, OCR labs e inclusiones críticas requieren confirmación humanaUna persona siempre revisa lo importante antes de que cuente como definitivo.
  5. Fail safe — prefiere decir “no sé” antes que inventarMejor admitir que no hay evidencia que dar una respuesta incorrecta.

Flujo RAG (simplificado)

Pregunta → Auth org+study → Embed → Vector search FILTRADO → ¿Similarity ≥ threshold? → No → insufficient_evidence → Sí → LLM grounded → Respuesta + citas → Audit log
Traducción: el usuario pregunta → el sistema confirma quién es y de qué estudio → busca en los documentos de ese estudio → si encuentra algo relevante, responde citando la fuente; si no, dice que no hay evidencia → todo queda registrado.

Flujo de ingesta

Upload PDF → Vercel Blob → Parse por página → Chunking → Embeddings OpenAI → pgvector → status: ready → Chat RAG
Traducción: subís el PDF → se guarda → se lee página por página → se parte en trozos → se indexa para búsqueda → queda listo para el chat.

Foso competitivo

  1. Grounding-only como contrato de productoPrometemos y medimos que solo responde con documentos — no es marketing vacío.
  2. 13+ políticas de compliance + implementación técnicaNo solo papeles legales: cifrado, auditoría y pruebas de que un cliente no ve datos de otro.
  3. BAAs/DPA firmados con procesadores antes de PHI realContratos con proveedores (nube, IA) antes de tocar datos reales de pacientes.
  4. Validación CSV con trazabilidad requisitos → pruebasDocumentación formal que liga cada función prometida con una prueba que la demuestra.
  5. Barrera regulatoriaUn competidor “rápido” tarda años en armar el equipo y la documentación que exige la industria.
